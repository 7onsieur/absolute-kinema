# animated-explainer v0.4-rc1 — Release Report

**Status: release candidate, for independent testing. Caption status on any specific render
remains UNVERIFIED until a human reviews that exact render — this report does not change that.**

## 1. What v0.4 adds

A new narration engine, **Kokoro-ONNX** (`narration.tts.engine: kokoro`), alongside the existing
espeak-ng and Piper engines from v0.3. It was built to directly answer two problems a human
reviewer found in v0.3: espeak-ng narration sounded "excessively robotic," and (for the project's
intended default British voices) captions could not be reliably forced-aligned at all.

Kokoro:
- Produces a genuinely natural-sounding neural voice, including real British voices (default:
  `bf_emma`).
- Gets its word timing **directly from the model's own per-phoneme duration output** at synthesis
  time — not from a separate forced-alignment pass — so it is unaffected by the PocketSphinx
  British-voice alignment failures documented in `DEVELOPMENT_REPORT_v0.3.md`.

This is a purely additive change. espeak-ng, Piper, user recordings, and silent (no-narration)
videos all continue to work exactly as in v0.3 — verified by the full regression suite below,
which exercises all of these paths and passed with no failures.

## 2. How we got here (background, already reviewed by the user before this build started)

1. An externally-authored `narration-kokoro.zip` module was evaluated for integration. It used a
   different, word-first tokenization approach that is immune to connected-speech elision, but it
   depended on the real `kokoro` + `torch` package, which requires Python <3.13 and could not
   resolve its dependencies in this sandbox's default Python 3.13 environment. It was not
   integrated.
2. Direct testing established that `kokoro-onnx` (a different, ONNX-based PyPI wrapper around the
   same underlying Kokoro model) **does** work in this sandbox, because it downloads its model
   weights from GitHub Releases rather than Hugging Face — and GitHub Releases were reachable here
   even though huggingface.co was not. This is the package actually integrated in v0.4.
3. A first isolated prototype, built directly against `kokoro-onnx`, produced a narrated demo that
   a human reviewer rated ~90% overall: the voice was accepted as "acceptable for the current free
   educational skill, although more expressive narration remains a future improvement," but
   captions were found to drift increasingly out of sync toward the end of the clip.
4. Root-cause investigation (`CAPTION_DRIFT_FIX_v0.4.md`) found the drift came from one specific,
   measured cause: Kokoro's phonemizer occasionally runs two adjacent words together into a single
   phoneme group with no gap between them (e.g. "far" + "more" → one group), which broke a 1:1
   word-to-phoneme-group assumption in the prototype's timing code for any sentence after the
   first occurrence. A first fix attempt (comparing each word's isolated phonemization against the
   real in-sentence groups) was tried, run, and found to fail — ordinary function words like "has"
   or "a" are pronounced differently in isolated vs. connected speech, a real effect discovered by
   running the code, not assumed. The adopted fix instead re-phonemizes successively longer
   in-context prefixes of the sentence to precisely localize exactly which words share a merged
   group, and estimates only that pair/run's real combined duration — never discarding the whole
   sentence's real timing the way the previous whole-sentence estimate did.
5. The user reviewed a corrected demo rendered with this fix and confirmed captions are now
   synchronized, and that the British voice remains acceptable. **This confirmation is what
   authorized the current v0.4-rc1 build** — the fix itself was developed and verified in an
   isolated prototype before any of it was integrated into the reusable skill.

## 3. What changed in the reusable skill (this build)

- **New module** `scripts/ae/kokoro_tts.py`: synthesizes narration for the skill's real,
  arbitrary `narration.script` (keyed by real sentence `id`s, not a hardcoded test script),
  recovers word timing with the verified merge-localization fix, and writes a
  `<audio>.word_timing.json` sidecar with the result.
- **`scripts/ae/tts.py`**: `kokoro` added as a third engine alongside `espeak`/`piper` in
  `synth_script()`, `list_voices()`, and `ensure_narration_audio()`'s caching (now keyed on
  `kokoro_model_dir` too, so a different model folder correctly triggers regeneration). Any stale
  sidecar of either kind (`.word_timing.json` or `.spans.json`) is deleted before regenerating, so
  a leftover sidecar from a previous engine can never be read against new audio it doesn't
  describe.
- **`scripts/ae/config.py`**: `kokoro` added to the allowed-engine list and `DEFAULTS`; an unknown
  Kokoro voice name is now a validation error, same as for Piper.
- **`scripts/ae/render.py`**, two fixes:
  1. `build_timing()` now checks for a `<audio>.word_timing.json` sidecar and uses it directly, with
     no alignment step, whenever one exists — generalizing what had been a prototype-only hook. A
     provenance-label bug was also found and fixed here: on a cache hit, the specific label (e.g.
     `"exact (from TTS engine's own duration output)"`) was being silently overwritten by a generic
     default; the label is now correctly restored from the cache.
  2. **New: render-cache invalidation.** Segment-video caching (the resumable-render feature) was,
     until now, keyed only on file existence — so changing narration, timing, or any other project
     setting between two renders of the same project could silently reuse an outdated video segment
     from before the change. This was observed directly during this project's own prototype testing.
     A new `_render_key()` captures everything that can affect what a segment should contain (the
     project file, the actual narration audio bytes, the resolved timing source and duration, the
     render scale, and the fps); `render()` now compares this key against the one recorded for the
     last render of that project and clears cached segments whenever it has changed.
- **Model handling**: `kokoro_tts.ensure_model()` downloads the ~140MB of model weights once, on
  first use, from `kokoro-onnx`'s own GitHub Releases. No weights are bundled in the skill package.
  A download failure raises a specific error naming both exact URLs and a manual-download
  alternative — there is no retry against a different (e.g. paid) source.
- **Licensing** (verified directly): the `kokoro-onnx` PyPI package is MIT-licensed; the Kokoro
  model itself is Apache-2.0. Both permit redistribution. The deliberate choice, consistent with
  this project's "do not bundle model weights unless redistribution is explicitly permitted"
  instruction, is still not to bundle them — download-on-first-use keeps the skill package small.
- **Documentation**: `SKILL.md`, `README.md`, and `templates/project_template.yaml` updated to
  cover the new engine, voice selection, model download behavior/licensing, and known limitations.
  `scripts/make_video.py voices --engine kokoro` lists all Kokoro voices and marks which one has
  actually been human-reviewed.

## 4. Testing performed

**Full regression suite:** `python3 -m pytest tests/ -q` → **44 passed, 1 skipped** (the skip is a
pre-existing, unrelated `NO_ESPEAK` marker), run twice in this session — once against the existing
development environment and once from a fresh virtualenv after installing `requirements.txt` from
scratch (see "Clean-environment install," below). No regressions in the espeak-ng, Piper,
user-recording, or silent-video code paths.

New tests added for this release (all exercised against the real, previously-downloaded Kokoro
model weights, not mocks, except where noted):
- `test_merge_localization_recovers_exact_timing_for_unaffected_words` — synthesizes the real
  sentence that originally exposed the drift bug and asserts exact timing is recovered for every
  word except the one merged pair ("far"/"more"), confirming the fix still works as integrated.
- `test_merge_localization_falls_back_safely_when_unverified` — confirms the recovery function
  returns `None` (triggering the safe whole-sentence fallback) rather than guessing, when its
  internal check can't be verified against the real groups.
- `test_build_timing_uses_word_timing_sidecar_without_alignment` — confirms `render.build_timing()`
  uses a `.word_timing.json` sidecar with no alignment call at all, and that the specific
  provenance label survives a cache hit (the bug described in §3 above).
- `test_render_cache_invalidates_when_narration_changes` — renders a project, changes the narration
  audio without changing the project file's text, re-renders, and confirms the previously cached
  segments are detected as stale and cleared, with the log saying so.
- `test_kokoro_narration_generated_and_treated_like_a_recording` — confirms real Kokoro narration
  produces a word-timing sidecar and starts life as `NOT VERIFIED`, exactly like any other engine
  (never auto-approved).
- `test_kokoro_render_produces_audible_mp4_and_srt_with_exact_timing` — full render through the
  integrated skill; confirms the output has an audio stream, an SRT is produced, timing is
  labelled exact, and QA reports no missing words.
- `test_kokoro_model_download_failure_raises_clear_error_not_silent_fallback` — confirms a
  download failure raises the documented, specific error rather than failing silently or falling
  back to a paid service (this one mocks the network call, since we want to test the failure path
  deterministically, not rely on an actual outage).

**Integrated-skill demonstration (not the isolated prototype):** a new project,
`demo_sky_is_blue/`, was created with `scripts/make_video.py new`, configured with
`narration.tts: {engine: kokoro, voice: bf_emma}`, and run through `validate` → `preview` →
`render` → `verify-captions` using only the skill's own CLI. Results:
- `validate` reported `timing exact (from TTS engine's own duration output)` and logged the
  expected merged-phoneme-group note for sentence 3 ("far"/"more"), confirming the fix is active
  in the integrated path, not just in isolated tests.
- The rendered `sky_is_blue.mp4` contains **both an h264 video stream and an aac audio stream**
  (confirmed directly with `ffprobe`), 21.19s, 1920x1080, 30fps.
- The exported `sky_is_blue.UNVERIFIED.srt` subtitles match the narration script and timing.
- The automated QA report shows no issues, `has_audio: True`, `possible_missing_words: 0`.
- `verify-captions` found 0 possible missing-word spots and produced `captions_review.md` for
  human reading. **Caption status is NOT VERIFIED and has deliberately been left that way** —
  `approve-captions` was not run. A human must watch this exact render with sound and run
  `approve-captions` themselves before its captions can be called verified.

**Clean-environment install test:** created a fresh Python virtualenv, ran
`pip install -r requirements.txt` with no prior state, and confirmed `kokoro-onnx` and every other
dependency installed cleanly with no errors; then re-ran the full test suite from inside that
virtualenv (pointing `AE_KOKORO_MODEL_DIR` at the already-downloaded model weights to avoid a
redundant network fetch) — same result, 44 passed, 1 skipped. Also smoke-tested
`make_video.py voices --engine kokoro`, `voices --engine espeak`, and `validate` on the existing
silent `water_cycle` example from that clean environment — all worked as expected.

## 5. What is tested vs. what remains unverified

**Tested and verified in this session:**
- Kokoro narration generation, exact-timing recovery, and the merge-localization fix, both in
  isolation and through the integrated skill's real CLI.
- Render-cache invalidation on a narration/timing change.
- MP4 audio + SRT output from the integrated skill.
- espeak-ng, Piper (code path only — see below), user-recording, and silent-video paths are
  unaffected (full regression suite passes).
- Clean-environment dependency installation.

**Explicitly NOT verified, and not claimed to be:**
- **Caption accuracy for any specific render is never machine-verified** — including the
  `demo_sky_is_blue` render produced in this session. Its caption status is correctly
  `NOT VERIFIED`. A human must watch it with sound and run `approve-captions` themselves.
- **Piper remains untested end-to-end** in this sandbox, same as in v0.3 — its voice files are
  hosted only on Hugging Face, which this environment cannot reach. The code path is exercised by
  existing tests with a stub, not with real Piper synthesis.
- **Only the default Kokoro voice, `bf_emma`, has been human-reviewed.** The other ten listed
  Kokoro voices are implemented and documented but have not been listened to by a person as part
  of this project.
- **The merge-localization fix recovers exact timing for every word except the specific merged
  pair/run** — that pair/run still gets a syllable-weighted estimate within its own real, measured
  combined duration, not frame-exact per-word timing. This is a documented, bounded limitation, not
  a bug.
- **No cross-platform testing.** Only Ubuntu 24.04/Python 3.13.18, same as v0.3.
- **This release candidate has not been independently tested outside this sandbox.**
