# animated-explainer v0.4-rc2 — Release Report

**Status: release candidate, for independent testing. Caption status on any specific render
remains UNVERIFIED until a human reviews that exact render — this report does not change that.**
This report covers only what changed between rc1 and rc2. For the full v0.4 feature set (Kokoro
integration, merge-localization fix, render-cache invalidation, licensing, etc.), see
`V0.4_RELEASE_REPORT.md`, which remains accurate background.

## Why rc2 exists

An independent fresh-session test of rc1 succeeded end to end — it installed the skill, built a
27.4-second earthquake animation with its own original diagrams, generated British Kokoro
narration, rendered the video, and exported synchronized captions. In the course of that, it
identified several real issues. rc2 fixes them. No new features were added; nothing else about
rc1's behavior was intentionally changed.

## Findings from the independent test, and how each was addressed

### Priority 1 — release blockers

1. **"Remove the developer-specific hardcoded Kokoro model path from `tests/test_ae.py`."**
   **Resolved.** The hardcoded sandbox path (`_DEV_MODEL_DIR = "/home/claude/..."`) was replaced
   with `kokoro_tts.DEFAULT_MODEL_DIR` — the exact same resolution logic the skill itself uses at
   runtime (the `AE_KOKORO_MODEL_DIR` environment variable if set, otherwise the standard per-user
   cache `~/.cache/animated-explainer/kokoro`). No test file contains an absolute, environment-
   specific path anymore.
2. **"Make the Kokoro integration tests locate downloaded models through the configured model
   cache or an explicit environment variable."** **Resolved** — same fix as above; verified by
   running the full suite with `AE_KOKORO_MODEL_DIR` set to a non-default folder and confirming
   the Kokoro tests picked it up correctly (not just by inspection).
3. **"Ensure the tests execute correctly in a fresh environment where model files are
   available."** **Resolved and verified.** Ran the full suite from a brand-new virtualenv (fresh
   `pip install -r requirements.txt`, no prior state) with `AE_KOKORO_MODEL_DIR` pointed at a
   folder with the model files: **46 passed, 1 skipped**, identical to the result in the ongoing
   development environment.
4. **"Fix the audio lead-in so the intended 0.6 seconds of silence exists as actual audio
   samples, rather than relying on an MP4 timestamp gap."** **Resolved.** The mux step previously
   used an ffmpeg `adelay` filter at mux time. It has been replaced with an explicit two-step
   process: the narration audio is normalized first, then a new `render._prepend_silence_wav()`
   helper bakes the lead-in into the WAV file as literal zero-valued PCM samples (verified by
   reading the samples back directly, not by trusting any filter or container behavior) *before*
   that WAV is ever muxed into the final container. Confirmed on the actual rendered demo: decoding
   the final MP4's audio to raw PCM and measuring RMS directly gives **0.0** for the lead-in region
   and ~8,141 (out of a 32,768 full-scale) immediately after it — real, measured silence followed
   by real, measured speech, not an artifact of container metadata.
5. **"Verify audio remains synchronised when decoded by tools that ignore container
   timestamps."** **Resolved and directly tested.** New test
   `test_lead_in_silence_is_real_in_rendered_output_not_a_container_trick` renders a project and
   decodes its output with `ffmpeg -f s16le` (raw PCM, no container timestamps involved at all),
   then checks the lead-in region is near-silent and the narration region immediately after is
   clearly audible. A second test,
   `test_prepend_silence_wav_adds_real_zero_samples`, checks the helper function itself at the
   sample level in isolation.
6. **"Preserve the existing human caption-approval system."** **Confirmed unchanged.** No part of
   `ae/captions.py` (the approval state machine) was touched. `approve-captions` was not run on any
   render in this session; caption status on the rc2 demo render is `NOT VERIFIED`, as it must be.

### Priority 2 — validation and documentation

7. **"Ensure validation distinguishes exact model-native timing from partially estimated
   timing."** **Resolved.** Previously, `build_timing()` labelled ALL Kokoro timing as plain
   `"exact (from TTS engine's own duration output)"`, even on a sentence where the merge-
   localization fix had to estimate one word pair/run. `ae/kokoro_tts.py` now records a
   per-word confidence tag in the `.word_timing.json` sidecar (backward-compatible: an entry
   without the tag is still read as exact), and `render.build_timing()` now reports
   `"exact for N/M words (...); K word(s) partially estimated - see SKILL.md 'AI narration'"`
   whenever any word in the render wasn't fully exact. Verified directly on the `sky_is_blue`
   demo's sentence 3 (the one with the known "far"/"more" merge): `validate` now prints
   `timing exact for 59/61 words (...); 2 word(s) partially estimated`, instead of a blanket
   `"exact"` that obscured this.
8. **"Correct the missing or misleading word-count and speaking-pace documentation."**
   **Resolved.** `SKILL.md`'s "Inputs to collect" step 2 previously gave a flat "30–40 words for
   10–15s" rule that doesn't actually hold for every project (the real pace/overhead depends on
   that project's `narration.offset` and `outro_hold`, which can differ from the defaults). It now
   gives a rough starting range tied to the *default* settings explicitly, and points to
   `validate`'s own per-project word-count/pace output and rule-of-thumb formula as the
   authoritative source.
9. **"Add `sudo apt-get update` to the Ubuntu installation instructions."** **Resolved** —
   added as the first line of the `apt-get install` block in `README.md`.
10. **"Fix broken documentation references and missing section headings."** **Resolved.**
    `README.md` and `SKILL.md` both cited `FRESH_SESSION_TEST_RESULTS.md` as if it were a bundled
    file; it has never actually been included in any release zip (checked v0.2's and v0.3's zips
    directly - confirmed absent from both). The citation was reworded to describe it accurately as
    a development-time record, not a file bundled with the skill. All other internal references
    (headings referenced by name, e.g. "AI narration"; numbered sections referenced from code
    comments, e.g. `CAPTION_DRIFT_FIX_v0.4.md §4`) were checked against the actual heading
    structure and confirmed to resolve correctly. The stale `## Limitations (v0.4-rc1, ...)`
    heading label was also corrected to `v0.4-rc2`.
11. **"Update the project template's version label."** **Resolved** — the comment at the top of
    `templates/project_template.yaml` said `(v0.2)`; updated to `(v0.4-rc2)`.
12. **"Make duration guidance consistent across the documentation."** **Resolved** — see item 8;
    the same rough-range-vs-authoritative-formula fix also removes the inconsistency between the
    SKILL.md narration-length guidance and `validate`'s own computed pace.
13. **"Ensure the fresh-session test plan accurately describes expected test results."**
    **Resolved.** The plan now explicitly covers both possible, equally-correct `validate` outcomes
    (fully exact, or partially estimated) instead of asserting only one; explains that Kokoro tests
    skip (not fail) when no model cache is present and how to point them at one; and adds the
    direct raw-PCM lead-in verification command so a reviewer can check item 4/5's fix themselves
    rather than taking this report's word for it. Renamed to
    `V0.4_RC2_FRESH_SESSION_TEST_PLAN.md` to avoid ambiguity with the rc1 plan it supersedes.

### Priority 3 — final verification (this session)

14. **Full regression suite:** `python3 -m pytest tests/ -q` → **46 passed, 1 skipped** (same
    unrelated `NO_ESPEAK` skip as before; two new tests added for the lead-in fix). Run against the
    final rc2 tree before packaging.
15. **Clean-environment Kokoro test:** fresh virtualenv, `pip install -r requirements.txt` from
    scratch, full suite re-run with `AE_KOKORO_MODEL_DIR` pointed at a pre-populated cache →
    identical result, 46 passed, 1 skipped.
16. **Narrated demonstration re-rendered with the corrected package:** `demo_sky_is_blue/`, through
    the integrated skill's own CLI (`validate` → `preview` → `render` → `verify-captions`), with
    Kokoro/`bf_emma`. `validate` now correctly reports the partial-estimate case for sentence 3.
17. **Verified directly on this render:** `ffprobe` shows an h264 video stream and an aac audio
    stream; the exported SRT matches the script and the scene timings printed by `validate`; the QA
    report shows `has_audio: True` and no issues; and — the specific rc2 fix — decoding the audio
    to raw PCM shows RMS 0.0 during the 0.6s lead-in and audible speech (~8,141 RMS) immediately
    after it, confirming the lead-in is real baked-in silence, not a container trick.
18. **Silent-video and user-recording paths:** the `water_cycle` silent example was re-validated
    and re-rendered, producing a video-only MP4 with no audio stream, as expected (its output was
    then restored to the exact pristine v0.3 baseline file afterward, since this check was only a
    smoke test and shouldn't leave an unnecessary diff in the package). The full regression suite's
    existing recording-based tests (forced alignment, `.spans.json`, caption approval) all passed
    unchanged, and the new lead-in test (`test_lead_in_silence_is_real_in_rendered_output_not_a_
    container_trick`) exercises the recording-based mux path directly with a synthetic "recording."
19. **Packaged** `animated-explainer-v0.4-rc2.zip` from a clean tree (no `work/`, caches, or demo
    output leaked in - checked explicitly) and confirmed it differs from the v0.3 baseline only in
    the files this release and v0.4-rc1 intentionally touched (`tts.py`, `config.py`, `render.py`,
    `make_video.py`, `kokoro_tts.py` [new], `requirements.txt`, `SKILL.md`, `README.md`,
    `templates/project_template.yaml`, `tests/test_ae.py`, plus the new `*.md` reports). Confirmed
    `v0.1.zip`/`v0.2.zip`/`v0.3.zip`/`v0.4-rc1.zip` are all still present and unmodified (checksums
    match their pre-rc2 state).

## What remains open (unchanged from rc1, not addressed by this release and not claimed to be)

- **Caption accuracy for any specific render is never machine-verified.** The `demo_sky_is_blue`
  render produced in this session is correctly `NOT VERIFIED`. A human must watch it with sound
  and run `approve-captions` themselves.
- **Piper remains untested end-to-end** in this sandbox (Hugging Face still unreachable here).
- **Only the default Kokoro voice, `bf_emma`, has been human-reviewed.**
- **The merge-localization fix still produces a bounded estimate**, not frame-exact timing, for
  the specific word pair/run it localizes — now clearly labelled as such, which is the rc2 fix,
  but the underlying bounded-estimate behavior itself is unchanged and still a documented
  limitation, not a bug.
- **No cross-platform testing.** Only Ubuntu 24.04/Python 3.13.18.
- **This release candidate has not been independently tested outside this sandbox** — rc1 was
  tested independently once, which is how these findings arose; rc2 itself has not yet had its own
  independent fresh-session test.

## Constraints honored

- v0.1/v0.2/v0.3 zips and v0.4-rc1.zip were not modified.
- The original "How AI Agents Use Skills" / AI internship video project was not touched.
- No paid services introduced or offered as a fallback.
- Nothing pushed or published to GitHub.
- No scope creep: no music, sound effects, voice cloning, or new animation styles were added -
  every change in this release traces directly to one of the 13 numbered findings above.
- Caption approval was never run by this agent on any render.
